**Decisions locked in for this plan:**
- PROVISIONAL runs render a client-facing report with the run quality stated in the header (PRD §17.1, stricter "COMPLETE only" alternative rejected — costs turnaround time on genuinely slow-to-settle sites).
- The connected (post-access) scan reuses the same rule IDs at a higher confidence ceiling — no separate connected rule registry (PRD §17.3).
- Campaign Signal Validator integration is out of scope for this plan (PRD §17.4) — a separate follow-up decision once this ships.
- The 0.60 coverage threshold (PRD §9.1.4) ships as a fixed constant; revisit only if it misbehaves against a real layer-weight profile (PRD §17.2).

That path does not exist and that directory (`alertService.ts`, `baselineManager.ts`, `findingsWriter.ts`, `ruleInterpretations.ts`, `tagConfigurationRules.ts`) is IHC drift-check services, unrelated to the Check Register. The real v2 rule registry — already substantially built — is `backend/src/services/validation/register/engine.ts` (`REGISTER`, `runRegister()`), alongside `L0.ts`–`L12.ts`, `layers.ts`, `scoring.ts`, `reporting.ts`, `contradictionGuard.ts`, `clickIdContention.ts`. ## Sprint 1 — Settle contract & run quality (PRD §7, Phase 1 — highest priority) — DONE
Shipped in commit `46af9dd`. Scoping decisions made during implementation, differing from the PRD's literal text:
- **No `crawl_pages`/`crawl_runs` changes.** The PRD's §7.1 names `crawl_pages`, but that table belongs to the unrelated Crawl Signal Extractor (CSE) feature (`services/crawl/`). The Direct Audit incidents this PRD exists to fix (OpenArt, Birkenstock) all run through the Audit Engine (`services/audit/journeySimulator.ts`, the `audits` table, per-run `StepCoverage[]` — not a per-page DB row), so all Sprint 1 work targets that path instead.
- **No new `settle_state` enum.** Reused the existing `SettleOutcome` (`'settled'|'quiet_period_cap_reached'|'navigation_failed'`, already load-bearing across L3/L5/`degradationSuppression.ts`/`coverageSuppression.ts`) rather than introducing a parallel `SETTLED|TIMEOUT|ERROR|NOT_REACHED` enum that would have meant a second source of truth for the same fact.
- **Retry policy**: `gotoAndSettleWithRetries()` (`dataCapture.ts`) — up to `settle_max_attempts` (default 2) additional attempts, escalating `navigationTimeoutMs`/`maxSettleMs` by 1.5x each retry; `StepCoverage` gains `settle_attempts`. Wired into `journeySimulator.ts`'s step loop in place of the old single-attempt `gotoAndSettle()` call.
- **`computeRunQuality()`** (`coverage.ts`) — `COMPLETE|PROVISIONAL|INSUFFICIENT` derived from `StepCoverage[]`: INSUFFICIENT when the declared conversion surface (a step distinct from landing that navigated successfully) never settled, or fewer than two steps settled overall. One implementation, reused by both `ReportCoverage.run_quality` (report header display) and a new durable `audits.run_quality` column (migration `20260911001_settle_contract_run_quality.sql`) — the export gate reads the column, never re-derives it.
- **Where "blocks client-facing render" landed**: not the `GET /:audit_id/report` read endpoint (still shows the operator the run internally, with run_quality stated in the header) — the actual gate is `POST /:audit_id/export`, which returns 409 for `INSUFFICIENT` before ever calling `getReport`/`generatePDF`. That endpoint is the real "client-facing artifact" boundary; the in-app report view is not.
- Frontend: run-quality badge in the `ReportPage.tsx` header, a distinct INSUFFICIENT banner in `ExecutiveSummary.tsx` ahead of the existing partial-coverage banner, export buttons disabled with an explanatory tooltip. Also fixed a latent bug in `auditApi.export()` — it never checked `r.ok`, so a blocked export would have silently downloaded a "PDF" containing the JSON error body.

## Sprint 2 — Evidence class, verdict lattice, severity ceilings (PRD §4, §8, §10) — DONE
Shipped. Scoping decisions and corrections made during implementation:
- **No `audit_findings` migration.** The PRD's §13.1 assumes a wide per-finding SQL table. The actual architecture persists the full `ValidationResult[]` array as JSONB inside `audit_reports.report_json` (`ReportJSON.technical_appendix.validation_results`) — every field added to the `ValidationResult`/`UnassessableFinding` types (`observation_confidence`, `verdict`, `severity_capped_from`, `kind`) already flows through that existing blob with zero schema change. `pages_evaluated`/`pages_in_scope`/`excluded_from_score`/`exclusion_reason` from the PRD's column list are likewise already covered by existing `ReportCoverage`/suppression-partition fields from prior sprints — nothing new needed there either. (The lighter `audit_results` table `saveValidationResults()` writes to is a narrower, pre-existing projection unrelated to this PRD's data model.)
- **`evidence_class` + `gated_direction`** added to all 95 rules (93 + the 2 splits below) in `types/audit.ts`'s `ValidationRule`, applied per-rule across `L0.ts`–`L12.ts`. Classification methodology: the PRD's §10 table names ~40 rules explicitly — applied verbatim, including its 3 mandated reclassifications. For the ~55 rules the PRD doesn't name (all of L4, L6, L7's non-PII rules, L8–L10, several L1/L2/L3/L5/L12 rules, and every OpenAI-era addition), applied the PRD's own stated principle (§3) directly: a rule whose FAIL is an absence claim defaults to `PRESENCE`; a rule whose FAIL is positive evidence of a problem defaults to `PRESENCE_INVERSE`; `DIRECT` reserved for cases the PRD names explicitly, or a narrow, justified exception — a rule inspecting the shape/format of a value a sibling rule already gates the existence of (e.g. `HASH_FORMAT_VALID`, `VALUE_NON_ZERO_AND_PLAUSIBLE`), where there's no incremental coverage risk beyond what's already gated. Every non-PRD-named classification carries an inline one-line comment explaining the call, so it's individually revisable.
- **`observation_confidence`/`verdict`** computed in `engine.ts`'s `runRegister()` (`deriveObservationConfidence()`, `deriveVerdict()`, `gatedDirectionFor()`) and attached to every result, additive alongside the existing `status`/`confidence` fields — no existing consumer's behavior changes. `CONFLICTED`/`CONFLICT` are not computed by new logic in Sprint 2 — they surface entirely through the existing `UnassessableFinding.kind` reclassification below; a general cross-signal engine that could set them from inside `runRegister()` itself is Sprint 4's job.
- **Severity ceilings** (`applySeverityCeiling()`): `PARTIAL` confidence caps at `high`, recording `severity_capped_from`. `UNSUPPORTED`/`CONFLICTED` results carry no severity ceiling logic of their own since they're already fully excluded from scoring/severity display by their own consumers (unaffected by this sprint).
- **`UnassessableFinding.kind`** added and all 4 existing producers reclassified: `clickIdContention.ts`/`contradictionGuard.ts` → `CONFLICT`; `coverageSuppression.ts`/`degradationSuppression.ts` → `NOT_OBSERVED`. Resolves the open judgement call `ATLAS_CLICKID_CONTENTION_CONTRADICTION_GUARD_PRD.md` flagged.
- **The 2 mandated rule splits**, both performed as real code changes (not just metadata): `GOOGLE_GLOBAL_SITE_TAG_PRESENT` → `GTAG_LOADER_PRESENT` (L1.5, any gtag loader) + `GOOGLE_ADS_AW_ID_PRESENT` (new L1.18, the AW- specific check, same logic the composite used to run); `FBP_AND_FBC_COOKIES_PRESENT` → `FBP_COOKIE_PRESENT` (L3.4, the real gated check, built on the click-ID PRD's W4 `_fbp`-only fail logic) + `FBC_COOKIE_PRESENT` (new L3.10, `test()` always returns `status: 'skipped'` — the general "any skipped result is `UNSUPPORTED`/`INCONCLUSIVE`" rule in `runRegister()` gives it the PRD's "always INCONCLUSIVE" behavior for free, no new engine plumbing needed).
- **`SERVER_CONTAINER_ENDPOINT_CONFIGURED` reclassified `INFERRED`** per the PRD; its dependent `SERVER_CONTAINER_FIRST_PARTY_DOMAIN` (not named by the PRD) reclassified `DERIVED`/gated-pass to inherit that same heuristic uncertainty, since it only ever runs when the INFERRED parent found something.
- **`declaration_source`** (`CLIENT_CONFIRMED|OPERATOR_ASSUMED|INFERRED_FROM_SITE`) implemented as **one value per audit run**, not per-platform as the PRD's text describes — Scan Inputs collects `declared_platforms` as a single flat array with no current UI for confirming platforms individually, so per-platform provenance has nowhere to attach; revisit if that UI changes. Threaded through `ScanInputs`/`StartAuditInputV2` → the `/api/audits/start` route (zod) → `createAudit`/`AuditJobData` → `orchestrator.ts` → `journeySimulator.ts` → `AuditData`, read by `DECLARED_PLATFORM_HAS_TAG` (L0.1) to cap its severity (defaults `OPERATOR_ASSUMED` when unset, per the PRD). Migration: `audits.declaration_source`. The PRD's other §8 behavior — a capped finding "renders as an open question rather than a defect" — needs the `client_question`/open-questions mechanism this rule doesn't yet use; that's Sprint 6's job, not Sprint 2's.
- **Registry completeness test** (`register.integrity`-adjacent, in `engine.test.ts`): asserts every rule in `REGISTER` declares `evidence_class`, every `DERIVED` rule declares `gated_direction`, and no non-`DERIVED` rule does.
- Bumped `REGISTER_VERSION` to `1.1.0` per its documented contract (Report Correctness Programme Part D4) — this sprint changed rule shape (new required fields) and split 2 rules.
- Fixed 3 pre-existing test files whose fixed rule counts/names the 2 splits broke (`L1.test.ts`, `L3.test.ts`, `register.integrity.test.ts`), plus added dedicated tests for the new engine functions, the severity ceiling, and the declaration_source cap. Full backend suite green apart from the same 2 pre-existing, unrelated failures already confirmed in Sprint 1 (Strategy Gate briefs, offline-conversion CSV validator).

## Sprint 3 — Output vocabulary binding & `outputLint` (PRD §5) — DONE

- **Fixed occurrences**: `L0.ts` (`DECLARED_PLATFORM_HAS_TAG` — "missing a base tag"/"NO TAG DETECTED — zero measurement..." → "no tag observed" family), `L3.ts` (`FBP_COOKIE_PRESENT` — "Missing: _fbp" → "_fbp not observed"), `L5.ts` (`PAGE_VIEW_FIRES_ON_EVERY_ROUTE` — "Missing page_view:"/"had no page_view" → "page_view not observed on:"; `MICRO_CONVERSIONS_FIRE` — evidence's literal `'missing'` → `'not observed'`), `L7.ts` (`PHONE_CAPTURED_WHERE_COLLECTED`/`NAME_AND_ADDRESS_CAPTURED_WHERE_COLLECTED` — "is missing from the conversion event" → "not observed on the conversion event"), `L12.ts` (`NO_CONSOLE_ERRORS_FROM_MEASUREMENT_CODE`'s `.expected` — "as broken" → "as functioning"), `L2.ts` (`GBRAID_CAPTURED_AT_LANDING`'s `.why`/`.expected` — "missing it silently drops" → "not capturing it silently drops"), `clickIdContention.ts` (`UnassessableFinding.reason` — "capture is broken" → "capture is impaired").

Also wired as a second, non-throwing check (`lintReportOutput()`, returns `[]` when clean) in the `/api/audits/:audit_id/export` route immediately before either `generatePDF()` call, returning a 500 with a clear message rather than an unhandled exception — this covers a persisted report saved before `outputLint.ts` existed.
- **Platform verdict label remap** (PRD §5.1): `Broken→No signal observed`, `At Risk→Partial signal observed`, `Healthy→Signal observed`, `Not Included→Not in scope`. Implemented as display-label maps only (`pdfGenerator.ts`'s `PLATFORM_STATUS_LABELS`, `PlatformImpact.tsx`'s `PLATFORM_STATUS_CONFIG`), not a rename of the underlying `PlatformBreakdown.status` enum — that enum is data read throughout scoring/reporting logic, not display copy. Also fixed 2 more `'Not Detected'` pills in `pdfGenerator.ts` and `SiteSetup.tsx` → `'Not observed'`, and `RunAuditForm.tsx`'s stale "reports Out of Scope, not Broken" helper text.

## Sprint 5 — Scoring & coverage gate (PRD §9)
Extends shipped coverage measurement, doesn't rebuild it: `scoring.ts`'s `calculateV2Scores()` already computes `ScoreCoverage{layers_tested, layers_total}` via `layerCoverage()` (and Report Correctness Programme Part D already fixed the denominator itself), but today "whatever ran, scores" — no floor exists.
- Add `min_confirmed_rules` + `layer_weight` to layer declarations; compute `coverage_ratio` from them.
- Score withheld (`score: null`, `score_withheld_reason: 'INSUFFICIENT_LAYER_COVERAGE'`) below the 0.60 threshold; render the Coverage Gate panel copy from PRD §9.2.
- Sub-scores follow the same gate; remove the current "renders `Moderate` on 0-of-2 layers" behavior → `Not assessed`.
- Wire Sprint 1's `run_quality` into this computation.
- Keep this distinct from Report Correctness Programme Part D2's `not_applicable`/`not_scanned` layer-display labels — that's layer-granularity coverage *display*; this is rule-granularity scoring *exclusion*. They compose, they don't merge.
