## Sprint 5 — Scoring & coverage gate (PRD §9) — DONE
Shipped. Scoping decisions and corrections made during implementation:
- **`layer_weight`** (`layers.ts`'s `LAYER_WEIGHT`) defaults to 1 for all 13 layers — the PRD declares this per layer but specifies no differentiated weighting scheme, so (matching the same "ship a fixed value, revisit only if it misbehaves" call already made for the 0.60 threshold, PRD §17 Q2) every layer gets equal weight until a real profile says otherwise.
- **`min_confirmed_rules`** is **not** a static per-layer count. A fixed absolute number would either go stale every time a rule is added/split (the exact drift class `ALL_V2_LAYERS`/`PLATFORM_MATCHER_HOSTS` already exist to prevent elsewhere in this register) or permanently exclude a legitimately rule-thin layer for a site_type that `applies_to` filters most of that layer's rules out of scope for. Operationalized instead as `MIN_CONFIRMED_RATIO` (0.5, shared default) — a layer needs at least half of its *applicable-this-run* rules resolved to a real `PASS`/`FAIL` verdict before it counts toward coverage at all (`scoring.ts`'s `layerScoringDecisions()`), computed live from this run's results rather than a stored constant. A layer with zero applicable rules is never scored — "never scored as zero" starts with nothing to average in the first place.
- **"CONFIRMED confidence" operationalized via the verdict lattice, not `observation_confidence` directly.** PRD §9.1 rule 1 says "score is computed only over rules at CONFIRMED confidence," but §4.3's own lattice already resolves a non-gated-direction `PARTIAL` result to a real `PASS`/`FAIL` verdict — filtering on `observation_confidence === 'CONFIRMED'` directly would incorrectly exclude that legitimate case too. `isScorable()` filters on `verdict ∈ {PASS, FAIL}` instead (exactly what §4.3 already defines as scoreable), falling back to the pre-Sprint-2 `status !== 'skipped'` check for a result with no `verdict` field (a v1-legacy result, or a hand-built fixture predating Sprint 2) — preserves old behavior for anything that never ran through `runRegister()`.
- **"Never silently averaged away" applied literally**: a layer that doesn't clear its own threshold is excluded from the score's numerator/denominator entirely, not just flagged in the coverage display — `inScoredLayers()` filters every score's underlying result set down to only its scored layers before computing pass rate/weighted health, even when the surrounding score's overall gate passed (e.g. 8 of 13 layers scored: the other 5 still get zero vote, never quietly blended in as if confirmed).
- **Sub-scores follow the identical gate at their own (smaller) layer scope** — Attribution Risk (L2+L3) and Optimization Strength (L6+L7) are both 2-layer scores, so under a 0.60 threshold "partial" (1 of 2 scored, ratio 0.5) and "withheld" (null) are the same condition; Data Consistency (L12 alone) is binary too. Fixed the exact bug PRD §9.3 names: `attribution_risk_level`/`optimization_strength`/`data_consistency_score` used to default to a "safe" label (`'Low'`/`'Moderate'`/`'High'`) when their layer(s) never ran at all — now `null` ("Not assessed"), never a fabricated default.
- **Sprint 1's `run_quality` is already wired in — structurally, not as a new parameter.** A degraded/coverage-affected result is already routed to `could_not_be_assessed` by `partitionCoverageAffected`/`partitionDegradedRuns` in `orchestrator.ts`, *before* `calculateV2Scores(assessable)` ever runs (this ordering predates Sprint 5). A `PROVISIONAL` run therefore naturally reaches scoring with fewer confirmed results already, which `layerScoringDecisions()` picks up automatically — no separate `run_quality` input needed in `scoring.ts` itself; the gate composes with the existing suppression pipeline rather than duplicating it.
- **`AuditScores`** (`types/audit.ts`, mirrored in the frontend's own copy) — all four score fields now `| null`; new `score_withheld_reason?: 'INSUFFICIENT_LAYER_COVERAGE'` (overall only; each sub-score's own `*_coverage` field already explains itself). Frontend's `AuditScores` gained the `ScoreCoverage`/`*_coverage` fields it was missing entirely.
- **Coverage Gate panel** (PRD §9.1.5/§9.2, exact copy) — new dedicated panel in both `pdfGenerator.ts` (drawn above the score-card grid) and `ExecutiveSummary.tsx` (a banner alongside the existing run-quality/limited-coverage ones), shown whenever the overall score is withheld; every score card renders "Not assessed" rather than a number/label when its own value is `null`.
